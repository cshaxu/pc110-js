# M2 T3 S6 8042 Evidence

## Claim

The selected PC/AT contract uses an 8042-compatible controller at `0x60` and
`0x64`; its command byte controls keyboard interrupt admission, its output
buffer carries controller or keyboard bytes, and its output port supplies the
A20/reset relation already exposed by S5.

## Evidence

- Level: Strong.
- Source: pinned read-only PCjs
  `machines/pcx86/modules/v2/chipset.js`, C8042 constants, data/status/command
  handlers, command-byte flags, output-port bits, and keyboard receive path.
- Reproduction: inspect those definitions beside focused original-TypeScript
  controller, adapter, PIC, output-port, and integration tests.

## Accepted Boundary

The project models controller-visible hardware state and raw keyboard-byte
ingress only. It does not emulate browser keyboard events, BIOS keyboard
services, a host input queue, a secondary controller, port `0x92`, firmware,
storage, display, DOS, or PC110 behavior.

## Regression Target

Each executable part preserves the native PIC, memory/A20, CPU-reset, RTC,
PIT, DMA, and system-port evidence while adding selected-controller coverage.

## P4 Integration Result

`pnpm run trace:rebuilt-rom` completed the existing bounded selected-ROM trace
after P3 composition. It executed two instructions to `F000:F907` and stopped
on `Unmapped I/O write port: 0x84`. The selected ROM did not yet reach `0x60`
or `0x64`; this is an honest unclaimed-device boundary, not evidence of an
8042 defect or a reason to add a synthetic response.
