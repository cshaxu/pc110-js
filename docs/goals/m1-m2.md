# M1 To M2 Goal Specification

## Status

Prepared for owner-authorized goal execution.

## Authorized Scope

Complete M1, create and verify `m1`, then complete M2, create and verify `m2`,
and stop. M3 and later milestones are outside this goal.

## Required Reading

Before work, read `AGENTS.md`, `CONTRIBUTING.md`,
`docs/planning/status.md`, `docs/planning/breakdown.md`, and
`docs/planning/execution-policy.md`. Read relevant requirement, baseline,
evidence, provenance, and governance documents before changing their subject.

## Inputs And Boundaries

- Use the read-only PCjs sibling checkout at `../pcjs` and its pinned baseline
  in `docs/baselines/pcjs-upstream-c7f21b4fa.md`.
- Use `../fdd.img` only after verifying SHA-256
  `FADEB3A27C6A0E1CF582DDE0B9AECB7E5D30678F2F967F2F4562F167CC0CB1D5`.
  Attach it read-only.
- Use relative paths. Do not modify sibling reference repositories or change
  global Git configuration.
- All repository artifacts must be English. Do not commit protected media,
  credentials, machine-specific absolute paths, or unreviewed protected
  screenshots.
- Do not add BIOS, DOS, PCDOS, filesystem, boot-repair, guest-service, or
  application-specific shortcuts.
- When needed, use a per-command safe-directory setting for `../pcjs`:
  `git -c safe.directory=D:/home/repos.hobby/pcjs`.

## M1: PCjs Reference Integration

Complete every M1 subtask in canonical order, starting at M1 T1 S1.

- Select and document one minimal complete PCjs PCx86 v2 80386 PC/AT machine.
- Record complete device, source, browser, build, firmware, configuration, and
  local-media dependency closure.
- Add a pc110-js-owned TypeScript runner or command that serves and opens the
  selected read-only PCjs reference machine in a browser.
- Fail clearly for missing sibling source, baseline mismatch, missing media, or
  asset hash mismatch.
- Follow `docs/requirements/m1-reference-browser-run.md` as a mandatory gate.
- Reach BIOS startup, boot-sector loading, and a visible DOS prompt in the
  browser through the selected PCjs hardware path.
- Add and manually verify `docs/quickstart/m1-reference.md`.
- Record browser proof, exact commands, boot markers, PCjs-to-M2 source maps,
  provenance, license boundaries, and excluded archival assets.
- Call the result the M1 PCjs reference baseline, never the standalone pc110-js
  implementation or golden baseline.

## M1 Snapshot Transition

After the M1 completion gate passes:

1. Ensure the final verified M1 commit is on clean `main` and pushed to origin.
2. Create `m1` from that exact `main` commit and push `m1` to origin.
3. Verify that `main`, local `m1`, and `origin/m1` resolve to the same commit.
4. Record the branch, remote push, and verification result in tracking and the
   milestone verification record.
5. Keep `m1` immutable and continue development on `main` only.

Do not begin M2 unless this transition succeeds. If `m1` already exists and
does not resolve to the expected commit, stop and request owner direction.

## M2: Standalone TypeScript 386 Golden Baseline

Complete every M2 subtask in canonical order.

- Build the project-owned TypeScript toolchain, browser and headless entries,
  profiles, registry, interfaces, variants, asset manifest, deterministic timing
  boundary, and generic `pc-at-386` profile.
- Implement the complete selected PCjs-supported 80386 CPU, memory, bus, and
  configured PC/AT hardware through project-native TypeScript modules.
- Use real hardware paths for PIC, PIT, DMA, RTC/CMOS, system ports, A20,
  keyboard controller, storage, video, input, interrupts, timing, and every
  selected-machine device. Do not leave placeholders active.
- Preserve PCjs-derived behavior with focused M1 comparisons, provenance,
  copyright notices, MIT obligations, and third-party notices. Write a one-page
  PCjs change report for every intentional behavior change.
- Keep generic implementations selectable through profile, registry, interface,
  and variant contracts.
- Remove all runtime dependency on `../pcjs` and copied PCjs JavaScript.
- Boot the known-good DOS floppy to a visible prompt in the standalone browser
  emulator and run required headless checks where feasible.
- Add and manually verify root `QUICKSTART.md` according to
  `docs/requirements/quick-start.md`.
- Record golden-baseline proof, limitations, performance envelope, regression
  commands, and assimilation/license audit results.

## M2 Snapshot Transition

After the M2 completion gate passes:

1. Ensure the final verified M2 commit is on clean `main` and pushed to origin.
2. Create `m2` from that exact `main` commit and push `m2` to origin.
3. Verify that `main`, local `m2`, and `origin/m2` resolve to the same commit.
4. Record the branch, remote push, and verification result in tracking and the
   milestone verification record.
5. Keep `m2` immutable and stop. Do not begin M3.

If `m2` already exists and does not resolve to the expected commit, stop and
request owner direction.

## Execution Records

- Work on exactly one subtask at a time.
- Create `docs/tracking/M<milestone>-T<task>.md` when each task begins. Give
  every subtask a section and update its concise `P<part>` entry in the same
  commit as every related change.
- Create subtask execution records where canonical planning lacks detail.
- Add compact English verification records for completed subtasks. Update
  evidence, provenance, change reports, TODOs, Quick Start, and notices when
  affected.
- Commit verified parts using
  `M<milestone> T<task> S<subtask> P<part>: <description>` and push completed
  verified subtasks promptly to `origin/main`.

## Stop Conditions

Stop and request owner direction if protected-media redistribution is required,
if a source license is unclear, if evidence requires a material architecture
change, if a current boot baseline cannot be restored within the active subtask,
if reference evidence cannot be resolved by a bounded experiment, or if the
required snapshot branch cannot be created safely.

## Completion

The goal is complete only when the M1 and M2 canonical completion gates pass,
`m1` and `m2` are verified and pushed, all required records are committed, and
M3 has not begun.
