# M1 T1 S4: Define Reference-Run Boundary

## Objective

Define the project-owned M1 reference-run boundary, including read-only source
resolution, local-media handling, and path safety.

## Non-Goals

- Do not implement the browser runner yet.
- Do not select a machine configuration or alter PCjs configuration files.
- Do not materialize or commit a PCjs source tree inside this repository.

## Proposed Boundary

- A project-owned local server resolves PCjs browser resources from the pinned
  Git object in `../pcjs`, not from the sibling worktree HEAD.
- The server accepts only normalized repository-relative resource paths and
  rejects traversal, Git metadata, and untracked filesystem access.
- The server exposes the known-good floppy only through a project-owned local
  endpoint after size and SHA-256 validation.
- Browser-visible paths remain relative to the project-owned local server.
- The server never checks out, resets, configures, or writes to `../pcjs`.

## Dependencies

- M1 T1 S2 pinned-object verification.
- M1 asset-policy and local floppy baseline records.
- PCjs machine XML and XSL resource-loading behavior.

## Verification

```powershell
git -c safe.directory=D:/home/repos.hobby/pcjs -C ../pcjs ls-tree -r --name-only c7f21b4fa2bdedac3d5c73094a6402fdc8b24c70 machines/pcx86
git -c safe.directory=D:/home/repos.hobby/pcjs -C ../pcjs show c7f21b4fa2bdedac3d5c73094a6402fdc8b24c70:machines/pcx86/xsl/machine.xsl
Get-FileHash ../fdd.img -Algorithm SHA256
```

## Completion Evidence

The pinned Git object can serve required PCjs files without reference-worktree
mutation, and the selected boundary preserves relative browser paths and local
asset validation.

## Stop Conditions

Stop and request owner direction if PCjs browser resource loading requires a
sibling checkout write, if a safe relative-path boundary cannot be enforced, or
if local floppy attachment requires committing protected media.
