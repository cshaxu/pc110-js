# M1 T2 S3: Inventory Runtime Dependencies

## Objective

Inventory the selected reference machine's firmware, disk, configuration,
browser, and build dependencies with redistribution and runtime-source
boundaries.

## Non-Goals

- Do not redistribute or commit PCjs ROMs, archive disks, or local DOS media.
- Do not build the standalone TypeScript runtime.
- Do not substitute a different BIOS, disk, or browser bundle.

## Dependency Classes

- Pinned PCjs source resources are read only and served only from the pinned
  sibling Git object during M1.
- The known-good floppy is a protected local input validated by size and hash.
- PCjs archival disks and private catalog paths are excluded from the M1 boot
  path.
- Browser build resources must be identified by their exact pinned paths.

## Verification

```powershell
git -c safe.directory=D:/home/repos.hobby/pcjs -C ../pcjs ls-tree -r --name-only c7f21b4fa2bdedac3d5c73094a6402fdc8b24c70 machines/pcx86/releases
git -c safe.directory=D:/home/repos.hobby/pcjs -C ../pcjs show c7f21b4fa2bdedac3d5c73094a6402fdc8b24c70:machines/machines.json
Get-FileHash ../fdd.img -Algorithm SHA256
Get-Item ../fdd.img | Select-Object Length
```

## Completion Evidence

Every required M1 dependency has an exact path or local identity, its runtime
role is known, and its redistribution status is explicit.

## Stop Conditions

Stop and request owner direction if required firmware or browser resources are
missing from the pinned object, if local media hash mismatches, if a dependency
lacks a usable license boundary, or if boot would require an excluded archive
disk.
