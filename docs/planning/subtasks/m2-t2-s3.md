# M2 T2 S3: 80386 Opcode Families And Privilege Behavior

## Objective

Implement the PCjs-selected 80386 execution core, supported opcode families,
exceptions, interrupts, and privilege behavior as project-native TypeScript.

## Non-Goals

- 80486 or PC110 CPU behavior.
- Firmware, DOS, filesystem, or guest-service shortcuts.
- Physical-memory, I/O, and platform-device implementation owned by later M2
  T2 and M2 T3 subtasks.

## Authorized Execution-Size Correction

On 2026-07-29, the owner authorized a bounded S3 execution-size architecture
correction. The CPU already retains the CS hidden-cache `D/B` attribute, but
most unprefixed execution paths still assume 16-bit operand and address sizes.
This correction introduces a project-native per-instruction context that derives
both defaults from CS, makes `66` and `67` select the non-default size without
cumulative toggling, and keeps SS stack-address width independent.

The correction is a constrained structural refactor, not a CPU rewrite. It must
preserve segment overrides, repeat prefixes, LOCK boundaries, fault EIP, trace
hooks, and device-facing interfaces. It excludes PC110, 80486, firmware,
guest-service, filesystem, and hardware work. PCjs remains the behavioral
authority, Intel 80386 behavior is the semantic requirement, and NXVM remains
an M2-only structural reference.

Rollout begins with context tests for both CS defaults, `66`/`67`, repeated
prefixes, SS stack width, instruction length, and fault EIP. Existing instruction
families then migrate incrementally, beginning with decode, ModR/M, immediates,
stack, and string paths. A family is not considered 32-bit-default capable only
because an operand-size-prefixed variant passes. The selected local ROM trace
and a bounded M1-reference comparison remain required evidence.

## Owner Priority Clarification

On 2026-07-29, the owner clarified the active delivery order: complete M2 T2
before requesting M2 T3 authorization. The immediate work remains S3 execution-
size migration plus the remaining 80386 instruction and system paths. Completion
requires focused conformance tests, a selected local ROM trace, an instruction
and system-feature coverage matrix, and bounded PCjs comparison records.

NXVM `vcpu.h` and `vcpuins.c` define a structural and coverage-reference floor
for the M2 CPU only. They do not define behavior, permit source translation, or
authorize NXVM BIOS, POST, I/O, or guest-service shortcuts. PCjs remains the
behavioral authority and Intel 80386 architecture remains the semantic
requirement. T3 remains out of scope until T2's documented gates are met and the
owner explicitly authorizes the transition.

## Initial Delivery Order

1. Define an instruction-fetch and execution boundary against a narrow memory
   contract. P2 implements the first single-byte CS:EIP fetch contract without
   a prefetch optimization. P3 adds NOP and HLT execution with explicit halted
   state while unsupported opcodes remain uncommitted. P4 adds the real-mode
   far-jump path required to follow a reset-vector control transfer. P5 adds
   real-mode register-immediate and relative-jump execution. P6 adds the
   reset-ROM `MOV r8, imm8` and `OUT imm8, AL` path through a narrow port writer.
   P7 adds the observed real-mode SAHF and CLI flag transitions. P8 adds the
   observed register-form LMSW transition with MSW fixed-bit semantics. P9 adds
   the observed register-form real-mode segment load. P10 adds reset-ROM port
   reads, TEST flag updates, and JNZ control flow. P11 adds the observed
   16-bit LOOP control flow. P12 adds reusable ModR/M decoding and observed
   register-form MOV and XOR execution. P13 adds the observed register-byte
   compare with complete 8-bit subtraction flags. P14 adds the observed JBE
   and byte-register XOR paths. P15 adds the observed single-bit byte shift and
   zero-count branch. P16 adds the reset-ROM CS-overridden memory far jump.
2. Add operand, flag, stack, and ModR/M helpers with focused conformance tests.
3. Add opcode families in documented, test-protected slices.
4. Add exception, interrupt, and privilege transitions through the same CPU
   execution path.

## Bounded Real-ROM Trace Boundary

P121 loaded the local, read-only selected DeskPro ROM into the current
project-native physical-memory implementation before executing any instruction.
The experiment stopped at mapping time: the contiguous RAM region created by
`ramBytes` occupies the selected `0xF8000` system-ROM window. The selected
machine contract instead requires discontiguous low RAM, ROM, a DeskPro RAM
window, and extended RAM regions. This is a planned M2 T2 S4 capability, not a
CPU opcode, firmware, or guest-service issue. No S4 scope was implemented or
advanced by P121; S3 remains active.

P124 repeated the bounded trace after P122 and P123 with a controlled
keyboard-controller status response only. It passed the newly covered ROM
instruction path and stopped on an `ES:B800` `REP STOSW` write because no VGA
memory device is mapped. The result classifies the next whole-machine boundary
as planned M2 T5 video hardware; it does not substitute a synthetic device for
the selected hardware model.
