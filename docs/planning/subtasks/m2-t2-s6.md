# M2 T2 S6: PCjs Differential CPU Validation Gate

## Objective

After S3 CPU, S4 memory, and S5 I/O/reset/stepping completion, prove the
project-native rebuilt CPU against a read-only PCjs CPU oracle one guest
instruction at a time. The gate is a verification harness, not a device bridge
or browser product runtime.

## Boundaries

- The harness is verification-only and is not a product runtime or distribution
  dependency.
- The rebuilt CPU and an isolated PCjs CPU oracle each execute exactly one
  instruction from independent but equivalent initial machine state. PCjs is
  allowed only inside this test-only oracle.
- The rebuilt CPU retains project-owned state, decode, execution, memory, port,
  reset, and trace contracts and has no runtime dependency on PCjs, NXVM, or
  the frozen legacy CPU.
- The harness does not instantiate PCjs devices, proxy their buses, or become a
  fallback for missing native hardware.
- Do not begin native M2 T3 device implementation until S3, S4, S5, and this
  final S6 gate pass.

## Parts

1. Replace the retired PCjs-device-proxy proposal with a documented, pinned
   PCjs CPU oracle boundary and normalized comparison schema.
2. Build a test-only lockstep harness with isolated memory and I/O journals for
   the rebuilt CPU and PCjs CPU, advancing each side by exactly one instruction.
3. Cover the NXVM opcode ledger in numeric-family order with mode, prefix,
   register/memory, flag, exception, privilege, paging, and fault-EIP cases
   where architecturally applicable.
4. Require a compact case-by-case entry in the project-wide compatibility
   register for intentional or irreducible differences. For a non-excluded
   divergence, inspect the NXVM handler and fix only the rebuilt implementation.
   When the rebuilt result is NXVM-aligned but differs from PCjs, retain it,
   record a scoped exception, and continue; escalate only ambiguous NXVM
   behavior, a rebuilt/NXVM mismatch, or a requested scope expansion.
5. Preserve the selected ROM trace as a whole-machine CPU boundary check. The
   standalone browser DOS workload remains an M2 native-machine completion gate
   after device migration; it is not implemented through PCjs proxies in S6.

## P3 Baseline Scope

P3 establishes the executable real-mode, no-I/O lockstep boundary. It compares
general registers, EIP, EFLAGS, and CS/DS/ES/SS normalized cache fields after
one instruction. P4 adds independent RAM-image deltas for changed bytes.
Port journals, exceptions, descriptor state, control/debug state, paging side
effects, protected mode, and prefix matrices remain explicit subsequent P5+
work; P3/P4 do not claim their validation.

## P5 Lockstep Dispatch Rule

The harness must not encode coverage as one handwritten test per opcode. A
program case supplies a byte stream, initial state, and instruction budget. For
each budgeted instruction, the common rebuilt runner-dispatch boundary captures
pre-state, dispatches exactly once, and captures post-state. The isolated PCjs
CPU performs one matching step, after which the harness compares the paired
post-state and changed-memory delta. A minimized program is evidence for a
failure, not the mechanism that selects opcode coverage.

## P6 I/O Journal Scope

The lockstep harness now accepts explicitly configured test-only port inputs.
It records each rebuilt and PCjs port access after every instruction as
direction, port, value, and width. This is a comparison adapter only; it does
not emulate a PC/AT device or permit synthetic responses in the ROM trace.

P7 replaces input-only declarations with a generic declared-port contract. A
port can have a deterministic input value or be output-only, while both CPU
paths journal access at its declared 8-, 16-, or 32-bit width.

P8 defines a logical-instruction PCjs step: debugger-style PCjs prefix steps
are aggregated with their opcode step before comparison. This aligns the oracle
with the rebuilt decoder's prefix-plus-opcode execution boundary.

P11 originally established the S6 exception record. P13 promotes it to the
project-wide `docs/governance/compatibility-exceptions.md` register.

P12 records the logical-AF conflict found while expanding generic real-mode
numeric-program coverage. P13 resolves it as EXC-002 and records the owner
rule to retain NXVM-aligned CPU behavior without per-case approval.

P14 adds passing generic real-mode numeric programs for selected `00-3F`
arithmetic, complete `40-5F`, and every `B0-BF` immediate-register encoding.
The shared dispatcher compares each instruction boundary; logical-AF behavior
remains governed by EXC-002.

P15 normalizes rebuilt RAM observations to changed-byte deltas, matching the
existing PCjs snapshot contract. It then adds passing generic real-mode programs
for `60-61` and immediate stack/IMUL forms `68-6B`.

P16 adds a passing generic real-mode `INSB`/`OUTSB` program using declared test
ports, independent RAM, and the existing I/O journal.

P17 adds a passing generic real-mode program for every short conditional branch
in `70-7F`, using zero displacements to keep the instruction stream linear.

P18 adds a passing generic real-mode arithmetic slice for Group One `80-83`
immediate register forms. Logical extensions remain subject to EXC-002.

P19 adds a passing generic real-mode `84-8D` slice for TEST, XCHG, general
MOV, and LEA. Segment-register forms and POP r/m remain separate matrices.

P20 adds a passing generic real-mode slice for NOP, accumulator XCHG, CBW/CWD,
and SAHF/LAHF. WAIT and far CALL remain separate event/control matrices.

P21 adds a passing generic real-mode moffs program for all `A0-A3` accumulator
loads and stores. String and accumulator TEST forms remain separate matrices.

P22 adds a passing generic real-mode byte-string program for MOVS, CMPS, STOS,
LODS, and SCAS. REP, DF, and segment-override forms remain separate matrices.

P24 adds a passing generic real-mode C0-C7 slice for immediate Group Two shifts
and immediate MOV. Returns, far pointers, and interrupts remain separate work.

P25 adds a passing generic real-mode C2/C3 slice for near returns with and
without immediate stack cleanup. Far returns, frame construction, and
interrupts remain separate work.

P26 adds a passing generic real-mode C4/C5 slice for LES and LDS word
far-pointer loads. Dword, address-size, protection, and invalid-register forms
remain separate work.

P27 adds a passing generic real-mode C8/C9 slice for ENTER and LEAVE
stack-frame operations. Nested frames, default-32 code, and independent
stack-address width remain separate work.

P28 adds a passing generic real-mode CA/CB slice for far returns with and
without immediate cleanup across code segments. Default-32 and protected-mode
returns remain separate work.

P29 adds a passing generic real-mode CC-CF slice for software interrupts and
IRET through prepared IVT entries. Clear-overflow, default-32, virtual-8086,
and protected interrupt-gate forms remain separate work.

## Acceptance

- Every in-scope ledger case has a passing normalized lockstep record or a
  reviewed exclusion entry with its exact reason and owner decision.
- The harness records register, segment/cache, descriptor, control/debug,
  memory, I/O, exception, fault-EIP, and paging-side-effect comparisons when
  those observations apply to a case.
- The harness remains outside the standalone product runtime, uses only a
  relative read-only sibling PCjs reference, and does not use PCjs devices.
- The full project gate, tracking, provenance, PCjs change report, and compact
  verification record pass before M2 T3 begins.
