# M2 T3 S1: 8259A-Compatible PIC Variants

## Objective

Implement project-native TypeScript master and slave 8259A-compatible PIC
variants for the selected PC/AT contract. The device must expose real command,
data, mask, request, in-service, priority, cascade, and CPU-vector behavior;
it must not synthesize firmware, DOS, or guest-service outcomes.

## Scope And Sources

- Behavioral authority: selected 8259A PC/AT behavior, checked against the
  pinned PCjs chipset reference at `../pcjs/machines/pcx86/modules/v2/chipset.js`.
- Product implementation: new project-native TypeScript under `src/devices/`.
- Required ports: master `0x20/0x21`, slave `0xa0/0xa1`, with the slave
  cascaded through master IRQ2.
- Required initial behavior: ICW1-4 initialization, OCW1 masking, OCW2
  specific/non-specific EOI, OCW3 IRR/ISR reads, fixed priorities, edge request
  latching, cascade arbitration, and vector acknowledgement.

## Non-Goals

- PCjs source translation or a PCjs runtime/device dependency.
- PIC automatic rotation, poll mode, special mask mode, buffered mode, or
  firmware-specific responses unless a later workload requires and documents
  them.
- PIT, DMA, RTC, keyboard controller, storage, video, PC110, BIOS, DOS, or
  filesystem behavior.

## Execution Order

1. Define a testable single-PIC state model and port protocol.
2. Add master/slave composition, IRQ2 cascade arbitration, and CPU vector
   acknowledgement.
3. Register the device through the rebuilt machine port bus and CPU interrupt
   admission boundary.
4. Add a browser-visible project-owned machine trace/status checkpoint; use it
   to select future differential diagnostics only when an actual workload
   finding requires them.

P2 implements the single-controller core: ICW1-4, OCW1 masking, OCW2
specific/non-specific EOI and fixed-priority control, OCW3 IRR/ISR selection,
edge-latched requests, and vector acknowledgement. Master/slave composition,
port-bus registration, CPU admission, and browser evidence remain later parts.

P3 composes two project-native controllers as the selected PC/AT master/slave
pair. It maps `0x20/0x21` and `0xa0/0xa1` as explicit 8-bit port ranges,
propagates pending slave work over master IRQ2, and acknowledges the resulting
CPU vector. CPU INTR admission remains P4 work.

## Verification

- Focused unit tests cover initialization, masking, priority, EOI, IRR/ISR,
  vectors, and cascade behavior.
- Integration tests cover port-bus registration and CPU interrupt admission
  without a PCjs device.
- Full gate: `pnpm run format`, `pnpm run build`, `pnpm run lint`,
  `pnpm run test`, and `git diff --check`.
- Manual browser evidence is required once the device is composed into the
  project-owned browser machine; it must not claim BIOS or DOS progress before
  the required native devices exist.

## Stop Conditions

- Stop for owner direction if the selected PC/AT contract requires a material
  chipset variant beyond the 8259A boundary, a protected asset, or a behavior
  conflict that cannot be resolved by the pinned reference and bounded tests.
