# M2 T3 S2: 8253/8254 PIT And Speaker Timing

## Objective

Implement a project-native TypeScript PC/AT PIT with three 8253/8254-compatible
counters at `0x40-0x43`. Counter 0 must raise IRQ0 through the native PIC;
counter 2 must expose a hardware timing output for later PC-speaker gating.

## Scope And Sources

- Behavioral authority: read-only pinned PCjs `chipset.js` PIT port, counter,
  IRQ0, and timer-2 wiring behavior, corroborated by focused component tests.
- Product code: project-native TypeScript under `src/devices/` and bounded
  rebuilt-machine composition.
- Required behavior: 16-bit binary counters, control words, latching,
  low/high byte access modes, modes 0 through 5, deterministic elapsed-tick
  advancement, counter-0 IRQ0 edge signaling, counter-2 output observation,
  and 8254 read-back where it affects the selected PC/AT contract.

## Non-Goals

- PCjs source or runtime imports.
- Host-clock timing, browser audio, firmware responses, BIOS/DOS shortcuts, or
  a synthetic IRQ source.
- Port `0x61` speaker/PPI gate, NMI, reset, or A20 glue; these belong to T3 S5.
- DMA, RTC, keyboard, storage, video, PC110, or filesystem behavior.

## Execution Order

1. Record PC/AT ports, counter ownership, timing source, IRQ0, and speaker
   wiring evidence; classify 8253 versus 8254 behavior and defer only bounded
   nonblocking compatibility questions.
2. Implement and test a standalone deterministic counter state model, including
   control, access/latch, modes, output transitions, and supported read-back.
3. Compose all three counters through the rebuilt 8-bit port bus; advance them
   from explicit emulated ticks and route counter-0 rising edges to the native
   PIC IRQ0 path.
4. Expose counter-2 output as a device signal, then verify native PIC/CPU
   delivery without implementing the later system-port gate or browser audio.
5. Extend the browser checkpoint with truthful PIT state only after the core
   path and focused tests pass.

## Verification

- Focused tests cover control words, latch/read sequencing, binary count zero
  semantics, modes 0-5, counter output transitions, read-back, port width,
  IRQ0/PIC/CPU admission, and counter-2 signal observation as applicable.
- The native browser checkpoint remains project-owned and does not claim a ROM
  boot, speaker sound, or DOS workload.
- Full gate: `pnpm run format`, `pnpm run build`, `pnpm run lint`,
  `pnpm run test`, and `git diff --check`.

P2 implements the standalone binary counter state model. It covers modes 0-5,
gate transitions, count and status latches, 8254 read-back selection, and
explicit tick-driven output rising edges. BCD, port registration, PIC wiring,
and the system-port speaker gate remain outside this part.

## Stop Conditions

- Stop for owner direction if selected-machine behavior requires a material
  timer/chipset variant outside 8253/8254, a protected asset, or an unresolved
  conflict between the PC/AT reference and bounded component evidence.
