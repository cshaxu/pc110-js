# M2 T3 S3: 8237-Compatible DMA And Page Registers

## Objective

Implement project-native TypeScript PC/AT DMA0 and DMA1 controller variants,
their page registers, and the master/slave cascade boundary. The implementation
must expose hardware register and transfer state without embedding FDC, BIOS,
DOS, storage, or guest-service behavior.

## Scope And Sources

- Behavioral authority: pinned read-only PCjs `chipset.js` DMA definitions,
  controller ports, page-register map, flip-flop behavior, cascade ownership,
  status, mask, mode, request, and master-clear handling.
- Product implementation: project-native TypeScript in `src/devices/` and
  bounded rebuilt-machine composition.
- Required ports: DMA0 `0x00-0x0f`, DMA1 `0xc0-0xde` on even ports, and
  selected PC/AT page registers `0x81-0x83`, `0x87`, `0x89-0x8b`, and `0x8f`.
- Required behavior: address/count low-high flip-flop, base/current registers,
  command, software request, masks, mode, status terminal-count clearing,
  master clear, request arbitration, single/demand/block transfer behavior,
  address increment/decrement, auto-initialize, channel-4 cascade, byte versus
  word channel addressing, and page-address calculation.

## Non-Goals

- PCjs source or runtime imports.
- FDC, disk, memory-card, BIOS, DOS, guest-service, or filesystem behavior.
- Host timers, implicit transfers, synthetic terminal-count responses, or a
  device-specific DMA callback hidden inside controller logic.
- PC110 DMA variants.

## Execution Order

1. Record selected ports, controller/channel ownership, page mapping, and
   cascade evidence; separate generic 8237 behavior from PCjs-specific hacks.
2. Implement and test an isolated controller state model with register
   flip-flops, mask/request/mode/status semantics, and explicit transfer grants.
3. Compose DMA0/DMA1 and page registers through the rebuilt 8-bit port bus;
   represent DMA1 channels as 16-bit ISA word transfers and channel 4 as the
   DMA0 cascade boundary.
4. Add a generic project-native memory-transfer adapter and explicit device
   request interface, without an FDC or storage implementation, then verify
   address/count/page/terminal-count behavior.
5. Extend the browser-native checkpoint with reset-only DMA state after the
   native core path and focused integration tests pass.

## Verification

- Focused tests cover register byte sequencing, masks, requests, modes,
  priority, status/terminal-count clearing, master clear, page mapping,
  increment/decrement, auto-init, byte/word transfer units, and cascade.
- Integration tests cover port ownership and explicit device request/transfer
  through project-native memory only.
- Browser evidence remains a reset-state checkpoint and must not claim FDC,
  firmware, storage, or DOS progress.
- Full gate: `pnpm run format`, `pnpm run build`, `pnpm run lint`,
  `pnpm run test`, and `git diff --check`.

P2 implements the standalone 8237 controller state model. It covers the shared
address/count flip-flop, base/current registers, command, request and mask
registers, mode, fixed or rotating priority, terminal count/status clearing,
master clear, auto-initialize, decrement, and byte/word physical addressing.
Port registration, paired-controller cascade, and data movement remain later.

P3 composes native DMA0/DMA1 instances and the selected PC/AT page registers
through the rebuilt 8-bit port bus. DMA1 uses only its even port addresses and
word-addressed local channels; reset clears both controllers. Channel-4 cascade
granting and actual memory/device movement remain P4 work.

## Stop Conditions

- Stop for owner direction if the selected PC/AT contract requires an unplanned
  chipset extension, protected asset, or material behavior conflict that cannot
  be resolved with the pinned reference and bounded focused tests.
