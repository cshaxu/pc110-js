# M2 T3 S4: RTC, CMOS, And Selected-Machine Configuration

## Objective

Implement a project-native TypeScript MC146818-compatible RTC/CMOS device at
`0x70` and `0x71`, with deterministic emulated-time advancement, IRQ8 wiring,
and selected PC/AT configuration bytes. The device must remain independent of
host time, firmware services, storage, and PC110-specific behavior.

## Scope And Sources

- Behavioral authority: pinned read-only PCjs
  `machines/pcx86/modules/v2/chipset.js` RTC/CMOS registers, ports, IRQ8
  relation, and selected configuration-byte definitions.
- Product code: original TypeScript under `src/devices/` with bounded rebuilt
  machine composition.
- Required behavior: 128-byte CMOS store, address/data port protocol, index
  masking, status A-D semantics, deterministic clock/calendar advancement,
  BCD/binary and 12/24-hour conversion, SET inhibition, periodic/update/alarm
  status, IRQ8 assertion, status-C acknowledgement, and selected configuration
  initialization/checksum behavior.

## Non-Goals

- PCjs source or runtime imports.
- Host wall-clock synchronization, browser timers, firmware services, BIOS/DOS
  shortcuts, storage configuration, or guest-service behavior.
- NMI delivery, reset, A20, and port `0x61` glue; the NMI-disable bit on
  `0x70` is only retained as an explicit S5-facing signal boundary.
- 8042 keyboard behavior, PC110 variants, persistent host CMOS storage, or a
  browser firmware/DOS workload claim.

## Execution Order

1. Record the selected PC/AT register map, configuration bytes, port contract,
   IRQ8 relation, and S5 NMI boundary.
2. Implement and test an isolated deterministic RTC/CMOS state model with
   calendar and status-register behavior.
3. Compose the local ports with the rebuilt bus and route acknowledged RTC
   interrupt conditions to native PIC IRQ8 without host scheduling.
4. Add selected generic-machine configuration initialization and checksum
   behavior only where the M1 machine contract establishes a need.
5. Extend the browser checkpoint with truthful reset-only RTC/CMOS status after
   focused integration evidence passes.

## Verification

- Focused tests cover index/data protocol, read-only and read-clear status
  behavior, BCD/binary and 12/24-hour conversions, SET, deterministic ticks,
  periodic/update/alarm status, IRQ8 acknowledgement, selected configuration,
  checksum, and port width where applicable.
- Integration tests cover native port ownership and RTC-to-PIC delivery with
  no PCjs runtime or host clock.
- Browser evidence remains a project-native reset-state checkpoint and must not
  claim firmware boot, storage, display, keyboard, or DOS progress.
- Full gate: `pnpm run format`, `pnpm run build`, `pnpm run lint`,
  `pnpm run test`, and `git diff --check`.

## Stop Conditions

- Stop for owner direction if the selected M1 machine contract needs an
  unplanned RTC/chipset variant, protected configuration asset, or material
  conflict that bounded component evidence cannot resolve.

## P2 State Core

P2 adds an isolated local MC146818-compatible 128-byte CMOS model. It uses a
fixed or explicitly injected initial date/time and explicit 32,768 Hz emulated
ticks. The model covers calendar rollover, BCD/binary and 12/24-hour forms,
SET, periodic/update/alarm status, status-C read acknowledgement, and the
selected checksum range. Port selection, IRQ8 wiring, NMI, host scheduling,
and selected-machine initialization remain later work.

## P3 PC/AT Port And IRQ Composition

P3 maps the local RTC/CMOS through `0x70` and `0x71` on the rebuilt 8-bit port
bus. Address bit 7 is retained as an observable NMI-disable signal without
performing NMI handling. `advanceRtc(ticks)` is the sole machine time entry
point and routes enabled local RTC events to native PIC IRQ8. There is no host
timer, browser clock, firmware response, storage configuration, or NMI glue.
