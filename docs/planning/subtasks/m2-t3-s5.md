# M2 T3 S5: System Ports, NMI, Reset, And A20 Glue

## Objective

Implement project-native TypeScript PC/AT system-port state, speaker/PIT gate
composition, NMI mask and delivery admission, reset sequencing, and A20 glue at
their actual device boundaries. The implementation must preserve the existing
RTC `0x70` NMI-mask signal and physical-memory A20 mapping without inventing
firmware or platform-specific shortcuts.

## Scope And Sources

- Behavioral authority: pinned read-only PCjs
  `machines/pcx86/modules/v2/chipset.js` PPI/8042 system-port definitions,
  CMOS NMI-mask path, NMI behavior, reset path, and A20 output-port relation.
- Product code: original TypeScript in `src/devices/`, `src/machine/`, and
  existing CPU/memory interfaces.
- Required behavior: `0x61` speaker gate and observable refresh/parity state,
  composition with native PIT counter 2, NMI enable state from RTC address bit
  7, explicit eligible NMI delivery, deterministic reset ordering, and A20
  control routed to project-native physical memory.

## Boundaries

- `0x70`/`0x71` RTC register behavior remains owned by T3 S4.
- The selected PCjs 5170/DeskPro A20/reset path is the 8042 output-port path;
  detailed command/status/controller behavior belongs to T3 S6. S5 provides
  only the narrow output, reset, and memory-wiring contract required by it.
- No synthetic port `0x92` is added: the selected source contract does not
  establish it as the required generic path.
- DeskPro RAM-window, ROM, chipset, PC110, BIOS/DOS, guest-service, storage,
  host clocks, and browser audio behavior remain outside this subtask.

## Execution Order

1. Record the selected ports, signal ownership, PCjs evidence, and explicit
   S6 8042 boundary.
2. Implement and test isolated system-port state, PIT2 speaker gating, and NMI
   mask/admission logic without host audio or device-specific services.
3. Compose the state with native PIT, RTC, physical memory, and rebuilt CPU;
   route only architecturally eligible NMI/reset/A20 events.
4. Provide the narrow 8042-facing output-port contract, then verify reset and
   A20 effects through project-owned memory and CPU state.
5. Extend the browser checkpoint with truthful reset-only system-port state.

## Verification

- Focused tests cover port width, PPI speaker gate, PIT2 output relation,
  refresh/parity status, RTC-controlled NMI masking, eligible NMI delivery,
  reset ordering, A20 aliases, and 8042 output-port boundary as applicable.
- Integration tests use project-native CPU, physical memory, PIC/PIT/RTC, and
  port bus only; no PCjs runtime or host time is permitted.
- Browser evidence is reset-state only and must not claim firmware boot, sound,
  keyboard operation, storage, display, or DOS progress.
- Full gate: `pnpm run format`, `pnpm run build`, `pnpm run lint`,
  `pnpm run test`, and `git diff --check`.

## Stop Conditions

- Stop for owner direction if a selected-machine NMI/reset/A20 variant requires
  an unplanned chipset model, protected asset, or conflict not resolvable from
  the pinned source and bounded component evidence.

## P2 System-Port State Core

P2 adds an isolated local generic `0x61` state model. It covers timer-2 gate,
speaker-data gate, refresh-status observation, and parity/I/O-check enable
state. The model exposes a hardware signal only and has no port mapping, PIT
wiring, host audio, keyboard-controller bits, DeskPro error lines, NMI delivery,
reset, or A20 behavior.

## P3 System-Port And PIT2 Composition

P3 maps the local system state through native 8-bit `0x61` I/O. Bit 0 drives
the native PIT counter-2 gate; bit 5 reports the local counter-2 output; the
speaker signal remains an observable boolean only. Reset clears the local
control state and disables the counter-2 gate. NMI, 8042 details, A20, reset
signals, host audio, and DeskPro-specific lines remain outside this part.

## P4 NMI Admission And Delivery

P4 adds a project-native non-maskable interrupt path that bypasses IF and the
maskable-interrupt inhibition boundary. The rebuilt machine accepts an explicit
NMI request only while the existing RTC address mask permits it, then delivers
real-mode vector 2 at the next machine boundary. No synthetic NMI source,
DeskPro error line, 8042 command protocol, A20, reset, firmware, or guest
service is added.

## P5 8042 Output-Port Boundary

P5 adds the narrow 8042 output-port state contract needed by this subtask. Bit
1 directly controls project-native physical-memory A20; bit 0 low requests a
CPU-only reset that preserves device reset ownership. The contract has no I/O
port mapping or command/status/data-buffer behavior; those remain T3 S6 work.
