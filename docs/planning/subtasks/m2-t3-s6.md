# M2 T3 S6: 8042 Keyboard Controller And Keyboard Boundary

## Objective

Implement a project-native, selected PC/AT-compatible 8042 keyboard-controller
path. It must model the data, status, command, output-buffer, command-byte,
output-port, and IRQ1 boundaries required by the selected machine without
turning browser input, BIOS services, or synthetic guest behavior into
controller behavior.

## Scope And Sources

- Behavioral authority: pinned read-only PCjs
  `machines/pcx86/modules/v2/chipset.js`, C8042 definitions and handlers.
- Product code: original TypeScript in `src/devices/`, `src/machine/`, and the
  existing native PIC, memory, and output-port contracts.
- Required ports: 8-bit data `0x60` and status/command `0x64`. Existing
  system-control port `0x61` remains S5-owned.
- Required controller behavior: output-buffer observation and consumption,
  command byte reads/writes, self/interface tests, keyboard enable/disable,
  input/output-port reads, output-port writes, keyboard-byte ingress, and
  IRQ1 admission through the native PIC.

## Boundaries

- The S5 `KeyboardOutputPort` remains the A20/reset signal authority. S6
  drives it only through the real 8042 output-port command path.
- S6 accepts raw keyboard bytes through a device-facing ingress boundary. Key
  mapping, browser events, scan-code generation, and UI focus remain T5 input
  work.
- Controller response timing will be deterministic and explicit. No BIOS
  polling workaround, guest-service shortcut, host keyboard event, or PCjs
  runtime is permitted.
- Secondary-controller, mouse, audio, port `0x92`, DeskPro-only wiring,
  firmware, storage, display, DOS, and PC110 behavior remain outside S6.

## Execution Order

1. Record selected 8042 ports, status/command ownership, IRQ1, output-port,
   raw-keyboard ingress, deterministic timing, and exclusions.
2. Implement and test an isolated controller state core for the selected 8042
   command/data families and output-buffer status.
3. Add the 8-bit PC/AT port adapter, native PIC IRQ1 wiring, and existing
   output-port callback without changing `0x61` ownership.
4. Exercise keyboard ingress, command-byte masking, buffer consumption,
   controller tests, reset/A20 effects, and deterministic response boundaries
   through machine integration tests.
5. Add a truthful browser reset/input-controller checkpoint. It must not claim
   browser-keyboard operation, firmware boot, display, storage, or DOS.

## Verification

- Focused tests cover 8-bit port width, data/status reads, command/data write
  sequencing, command-byte bits, output-buffer status, controller tests,
  keyboard enable/disable, raw-byte ingress, IRQ1, output-port A20/reset, and
  reset state.
- Tests cover unavailable or disabled input without inventing a response, and
  preserve native PIC, memory, CPU-reset, RTC, PIT, DMA, and system-port
  behavior.
- Browser evidence is controller reset/checkpoint only unless a later native
  firmware/storage/display workload proves more.
- Full gate: `pnpm run format`, `pnpm run build`, `pnpm run lint`,
  `pnpm run test`, and `git diff --check`.

## Stop Conditions

- Stop for owner direction if selected-ROM execution requires an undocumented
  controller timing, a second controller, an unplanned chipset model, or a
  machine-specific input source that cannot be established from the pinned
  reference and bounded component evidence.

## P2 Controller State Core

P2 will add the isolated command/data/status state and selected command-family
semantics. It will not map I/O ports, raise PIC IRQ1, accept browser events,
or reset the machine.

P2 adds a one-byte output-buffer model with an explicit output source. It
handles `0x20`, `0x60`, `0xAA`, `0xAB`, `0xAD`, `0xAE`, `0xC0`, `0xD0`, `0xD1`,
`0xE0`, and output-port pulse commands. Raw keyboard ingress is accepted only
when the keyboard clock is enabled and the output buffer is empty; it reports,
but does not route, an eligible IRQ1 request. Controller responses are
deterministic and do not use a BIOS polling delay.

## P3 PC/AT Adapter And IRQ1 Composition

P3 will map `0x60`/`0x64`, compose eligible output-buffer events with native
PIC IRQ1, and route `0xD1` output-port data through the S5 contract. It will
not add scan-code translation, browser mapping, firmware, or guest services.

P3 adds a byte-only adapter around the P2 core and machine-owned raw-byte
ingress. Only accepted, interrupt-enabled keyboard bytes raise native IRQ1;
controller replies remain local output-buffer events. The adapter forwards
output-port updates and processor-reset pulses through existing narrow S5
callbacks while leaving the system-control port `0x61` untouched.

## P4 Integration And Timing Evidence

P4 will add bounded machine integration evidence for buffer lifecycle,
controller command responses, keyboard-byte ingress, IRQ1, and output-port
effects. Any remaining selected-ROM timing gap will be recorded rather than
covered by a synthetic response.

P4 confirms controller output-buffer lifecycle, keyboard IRQ1 eligibility,
output-port A20/reset effects, and self-test reset state through the rebuilt
machine. The selected-ROM trace remains bounded at the unrelated, unclaimed
`0x84` I/O write at `F000:F907`; no response is added for it.

## P5 Browser Checkpoint

P5 will expose only reset-state controller information in the existing browser
checkpoint and manually verify that it remains truthful and error-free.
