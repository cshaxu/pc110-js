# M2 T4 S3: Selected Fixed Storage Hardware

## Objective

Implement the selected DeskPro 386 primary AT fixed-disk controller as
project-native TypeScript hardware. The selected M1 configuration declares an
IBM AT Type 5 fixed disk: 940 cylinders, 6 heads, 17 sectors per track, and
512-byte sectors.

## Scope And Sources

- Behavioral authority: pinned read-only PCjs `hdc.js`, `driveinfo.js`, and
  the selected IBM AT Type 5 configuration.
- Product code: original TypeScript under `src/devices/`, `src/machine/`, and
  `src/firmware/`; no PCjs runtime or source import.
- Primary command block: `0x1F0`-`0x1F7`; device control: `0x3F6`.
- Controller signal: native IRQ14 through the PC/AT PIC cascade.
- Media contract: raw CHS sector media; no DOS, filesystem, INT 13, hidden
  host file access, or synthetic boot-sector response.

## Execution Order

1. Record geometry, register ownership, status/error semantics, reset, IRQ14,
   and raw-media evidence.
2. Add a TypeScript raw fixed-drive contract with Type 5 geometry, attachment,
   presence, read-only state, and CHS bounds validation.
3. Add the complete primary command-block register family and device-control
   reset behavior with byte/word data-port access rules.
4. Implement controller diagnostics, recalibrate, seek, set parameters, and
   read-verify behavior with real status/error transitions.
5. Implement PIO READ DATA across CHS sectors, data-request status, register
   progression, IRQ14, and error paths.
6. Implement PIO WRITE DATA and write-protect behavior only after read paths
   are verified. Implement IDENTIFY only when a selected workload requires it.
7. Compose the device in the selected machine and verify firmware-issued
   fixed-disk traffic without media auto-mounting or boot shortcuts.

## Boundaries

- No PCjs runtime, copied JavaScript, BIOS/DOS service, filesystem, or guest
  result shortcut is permitted.
- The device must not fabricate an attached disk. Raw media attachment remains
  explicit and validates exact geometry.
- Unsupported commands must produce controller-defined error state, never an
  unimplemented-port sink or a guest-service response.
- Browser file selection and persistent host storage remain outside this device
  core and are later presentation/configuration work.

## Verification

- Focused tests cover all owned ports, 8/16-bit data access, register masks,
  status/error transitions, control reset, drive selection, CHS bounds, IRQ14,
  and no-media/write-protect cases.
- Raw-media tests cover geometry, attach/eject, ready, write-protect, sector
  transfer, and no filesystem interpretation.
- Machine tests cover PIC cascade delivery and selected profile composition.
- Selected-ROM and later DOS workload traces record real controller traffic.
- Full gate: `pnpm run format`, `pnpm run build`, `pnpm run lint`,
  `pnpm run test`, and `git diff --check`.
