# M2 T5 S1: Selected VGA Hardware And Video Memory

## Objective

Implement a project-native selected IBM VGA model, including the MDA/CGA
compatibility probes exercised by the selected DeskPro 386 ROM, VGA register
state, video-memory decoding, planar write/read behavior required by firmware
and DOS, and a framebuffer-facing state contract.

## Scope And Sources

- Behavioral authority: pinned read-only PCjs `video.js`, selected DeskPro 386
  VGA configuration, and IBM VGA register configuration.
- Product code: original TypeScript in `src/devices/`, `src/memory/`,
  `src/machine/`, and later browser presentation modules.
- Selected ROM boundary: `OUT 0x3B8, AL` at `F000:BB30`; this is the MDA
  compatibility mode register probe during VGA-machine firmware initialization.
- Required VGA domains: MDA/CGA compatibility ports, CRTC, attribute,
  sequencer, graphics controller, miscellaneous output, DAC, status, and
  selected VGA memory windows.

## Boundaries

- MDA compatibility ports are modeled as VGA-compatible probe/register state,
  not as an unselected standalone MDA display or printer implementation.
- Browser canvas/DOM is a presentation client, not video hardware state.
- Video memory, plane/latch semantics, timing/status, and register access must
  remain hardware contracts. No BIOS text service or DOS screen shortcut.
- Start with exact selected firmware paths and expand by full register family;
  do not make individual ROM writes silent sinks.

## Execution Order

1. Record MDA `0x3B8` and selected IBM VGA compatibility evidence, port and
   memory ownership, required boot paths, and non-goals.
2. Add isolated MDA compatibility CRTC/mode/status state sufficient for the
   observed probe family, with retained register behavior and no renderer.
3. Add retained CGA compatibility CRTC/mode/color/status state before the main
   VGA register banks, because the selected ROM initializes that complete
   compatibility group first.
4. Add isolated VGA register banks and selected indexed-register semantics.
5. Add project-native VGA memory planes, address mapping, latches, and read/
   write modes needed by selected firmware and text display.
6. Compose ports and memory into the selected profile, re-run ROM trace, and
   classify the next unavailable device boundary.
7. Add browser framebuffer presentation only after hardware state is stable.
8. Add an explicit physical-memory device aperture and compose the native VGA
   aperture through it. Hardware windows may cover writable RAM holes, but may
   not conceal immutable ROM mappings or each other.

## Verification

- Focused tests cover every owned byte-wide port, indexed-register behavior,
  compatibility probes, mode/status state, video-memory mapping, planes,
  latches, and selected read/write modes.
- Integration tests prove the selected ROM crosses `0x3B8` through retained
  native state and that generic PC/AT behavior remains explicit.
- Browser tests inspect a real project-owned framebuffer only after the device
  core and machine composition have passed.
- Full gate: `pnpm run format`, `pnpm run build`, `pnpm run lint`,
  `pnpm run test`, and `git diff --check`.

## Stop Conditions

Stop for owner direction only if selected VGA behavior depends on an unsupported
proprietary ROM, protected asset, or unresolvable source conflict. Do not stop
for ordinary register, memory, or rendering work.

## P2 MDA Compatibility

P2 adds the complete retained MDA CRTC alias family at `0x3B0`-`0x3B7`, mode
at `0x3B8`, and deterministic status at `0x3BA`. It is composed as VGA-visible
compatibility state, not an MDA renderer or printer. The selected trace reaches
`F000:BB36` after 224 instructions and stops at the next CGA-compatible mode
port, `0x3D8`.

## P3 CGA Compatibility

P3 adds the complete retained CGA CRTC index/data family at `0x3D4`/`0x3D5`,
mode at `0x3D8`, color select at `0x3D9`, and deterministic retrace status at
`0x3DA`. It remains compatibility register state rather than a CGA renderer,
framebuffer, or video-memory implementation. The selected trace reaches
`F000:BB44` after 231 instructions and stops at VGA attribute-controller port
`0x3C0`.

## P4 VGA Attribute Controller

P4 adds the complete retained attribute-controller register bank at
`0x3C0`/`0x3C1`: palette registers, mode, overscan, color-plane enable,
horizontal panning, and color select. It models the index/data flip-flop,
palette-enable gating, and the status-one read reset through the existing
`0x3DA` compatibility device. The selected fixed-budget trace completes 1,000
instructions at `F000:9C05`; this is not a claim of a completed VGA renderer,
framebuffer, memory plane, or boot.

## P5 VGA Sequencer And Trace Diagnostics

P5 adds the complete retained sequencer bank at `0x3C4`/`0x3C5`, including
reset, clocking, map-mask, character-map, and memory-mode registers. The
selected-ROM trace now accepts an optional positive instruction budget and an
optional diagnostic tail while preserving its 1,000-instruction default.

The longer trace reaches `F000:BBB4`, a ROM POST failure loop after a zero PIT
counter observation. An attempted instruction-count-to-PIT-tick coupling was
rejected before commit because it generated premature IRQ0 delivery and an
invalid low-memory vector. A later project-native machine scheduler must use
CPU cycle accounting rather than instruction counts. This is outside P5's
sequencer scope and does not authorize firmware behavior or synthetic timer
responses.

## P6 Cycle-Accounted Trace Recovery

P6 adds a project-native CPU step-cycle result and an exact integer-ratio
machine scheduler for the selected DeskPro 386 PIT domain. It also preserves a
documented 80386 compatibility rule for `0F 20` and `0F 22`: the early-386 MOD
field is ignored, as required by the selected ROM. The 70,000-instruction trace
now crosses `F000:87A5 -> 0018:87AA` and returns through
`0018:87D7 -> F000:87DC`.

The scheduler's estimator is deliberately bounded: it provides explicit
cycle charges for current machine scheduling, while full Intel 80386 timing
coverage, memory/bus penalties, RTC, and video clock domains remain a
`TODO(High)` closure item. No firmware response, synthetic device event, or
PCjs runtime behavior is introduced.

## P7 PC/AT Refresh Status

P7 composes native PIT counter-1 output into bit 4 of the existing PC/AT
system-control port `0x61`, while preserving timer-2 and speaker behavior. The
selected trace moves past the firmware refresh polling loop from `F000:B587`
to `F000:B5F7`; it does not claim browser audio or complete machine scheduling.

## P8 Video Aperture Contract

P8 adds the project-native physical-memory device-aperture contract required
for VGA memory. Address normalization, including A20, precedes device lookup;
a device can overlay writable RAM but cannot overlap immutable ROM or another
device. This is an owned hardware-bus contract, not a VGA plane, renderer, or
browser presentation claim.

## P9 VGA Graphics Controller

P9 adds the complete retained VGA Graphics Controller register family at
`0x3CE`/`0x3CF`: set/reset, enable set/reset, color compare, data rotate,
read map, mode, miscellaneous graphics, color don't care, and bit mask. The
next VGA memory part consumes this native state for plane/latch behavior; P9
does not claim that the aperture, planes, or renderer are complete.

## P10 VGA Planar Memory

P10 composes native A0000-BFFFF VGA aperture memory with four 64 KiB planes,
read latches, selected memory windows, chain-four and even/odd addressing, and
Graphics Controller read/write modes zero through three. Rendering remains a
separate client of this hardware state.

## P11 VGA CRTC Ownership

P11 transfers the shared `0x3D4`/`0x3D5` indexed CRTC ports from standalone
CGA compatibility state to a native VGA CRTC. CGA mode, color, and status ports
remain retained compatibility behavior. The native CRTC owns timing, display
start, and cursor register state for later presentation.

## P12 VGA DAC And Miscellaneous Output

P12 adds native Miscellaneous Output and DAC state: `0x3C2`/`0x3CC`, palette
masking, read/write DAC addresses, 6-bit RGB triplets, and automatic component
and address advancement. The DAC palette is exposed as hardware state for a
later renderer, not duplicated in the browser UI.
