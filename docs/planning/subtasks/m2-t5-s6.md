# M2 T5 S6: Structured Trace, Status, And Error Presentation

## Objective

Provide bounded diagnostic presentation for the standalone browser workload
without changing native emulation behavior or adding a PCjs product dependency.

## Scope

- Keep native status and trace data observational.
- Allow an explicit development-only same-origin PCjs diagnostic panel for
  short paired investigations.
- Share pinned-resource validation between the standalone reference server and
  the Vite diagnostic route.

## Boundaries

- PCjs is an oracle only and is never imported by the product build or default
  browser path.
- The panel must use verified local media and an opt-in PCjs `pc110` branch
  probe.
- No firmware, DOS, input, timing, or device workaround is authorized here.

## Verification

- Run the full project gate.
- Verify the diagnostic Vite route returns the temporary machine XML and the
  instrumented PCjs bundle.
- Confirm the native page exposes the panel only with explicit development
  query parameters.

## Stop Conditions

Stop the paired comparison and return to native implementation when browser
tooling cannot render the PCjs XML/XSL surface or when no bounded mismatch is
available to classify.
